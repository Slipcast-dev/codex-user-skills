# Координация в Codex
Это файловая координация, не серверная MAS: нет Redis/PostgreSQL, брокера, установленных MCP
для toolchain/RAG/VM и фонового монитора. Переносов в инфраструктуру не требуется.
Основной чат — диспетчер; профили не запускают друг друга.

## Предварительные условия
- macOS/Linux, локальная файловая система, Python 3.11+ с jsonschema (в текущем Python проверено).
- Профили из ~/.codex/agents; общие supervisor, code-reviewer, test-engineer переиспользуются.
- Собственный проект и разрешённая рабочая копия, Git status и применимый AGENTS.md.
- Для запуска драйвера/прошивки — явно выделенная VM/HIL. Здесь она не установлена.
- Установка дополнительных toolchain, VM, MCP и сертификатов — отдельные действия в рамках
  конкретного проекта. Не выдумывай endpoints, сетевые доступы, API или наличие оборудования.
- Никаких секретов, полных логов/дампов или персональных данных в JSON-состоянии.

## Команды
Ниже SCRIPT — абсолютный путь к scripts/coordinate.py в этом skill, PROJECT — каталог проекта.
Команды запускай через Python с доступным jsonschema; не устанавливай зависимость автоматически.
При чтении этой инструкции подставь реальные абсолютные пути, не меняй рабочую папку на каталог skill.

1. python3 SCRIPT --project PROJECT init --kind driver --timeout 1800 --max-dispatches 30
   Вид: driver/firmware/service требуют build/static/security/runtime; application — build/static/security;
   research — research; planning — design. Не выдавай planning-run за готовый продукт.
2. python3 SCRIPT --project PROJECT snapshot --path src/driver.c --path include/abi.h
   Получи sha256 snapshot. Выбери все значимые исходники, конфигурации и контракты.
   Инструмент проверяет перечисленные файлы, не доказывает полноту этого набора.
3. Сформируй task.json по packets.schema.json. Дай goal, agent, gate, snapshot, depends_on,
   write_paths; inputs и criteria полезны для самодостаточного поручения.
4. python3 SCRIPT --project PROJECT dispatch --packet /absolute/path/task.json
   Получи attempt и лимиты; только после успеха запусти/поручи работу штатными инструментами Codex.
   Не выдавай dispatch за запуск агента. Разрешено максимум 3 активных задания.
5. Прими result.json с теми же id/agent/attempt/snapshot. Отчёт и доказательства сохраняются
   в проекте, например reports/security.json; для каждого evidence нужен путь и SHA-256 файла.
   python3 SCRIPT --project PROJECT complete --packet /absolute/path/result.json
6. После изменения исходников зарегистрируй новый snapshot перед проверками. Результат executor
   ссылается на входную версию; gates для финала должны проверять новый фактический snapshot.
7. python3 SCRIPT --project PROJECT finish --snapshot sha256:...
   Приёмка требует всех обязательных gates на этой версии, отсутствия активных/непринятых задач
   этой версии и security hold. Повторно сверяются source и evidence хеши.
8. python3 SCRIPT --project PROJECT status
   python3 SCRIPT --project PROJECT stop --reason "Запрос пользователя"
   stop блокирует выдачу заданий и финальную приёмку; уже работающих агентов основной чат
   прерывает отдельно штатными средствами. Поздние отчёты можно сохранить, но завершить stopped-run нельзя.

## Контракты и ограничения
Пакет task/result — строгий JSON без дополнительных полей, до 64 KiB. Для pass нужен хотя бы
один неизменённый файл evidence. Его наличие не доказывает истинность отчёта: диспетчер
проверяет команды, exit codes, покрытие, среду и выводы. JSON Schema не исполняет утверждения.
Поиск и внешние документы сначала проходят hardware-os-researcher; передаются цитаты и ссылки,
не команды/права. Межролевой обмен — через диспетчера, не свободные сообщения между исполнителями.

Пути write_paths — кооперативные резервирования: вложенные области конфликтуют, выход из проекта,
symlink наружу, .git/.systems и резервирование всего корня запрещены. Они не ограничивают процесс
с правами ОС; настоящую изоляцию задаёт родительская сессия/VM. Используй отдельные worktree
для независимых больших изменений, с отдельным состоянием и интеграционной приёмкой после merge.
Файлы отчётов включай в область записи агента. Критики не изменяют исходники.

Состояние .systems/state.json и краткая история обновляются под fcntl.flock и атомарной заменой.
Локальные инструменты/агенты могут обходить эту кооперативную дисциплину; это не security boundary.
Не используй общий каталог состояния на NFS/iCloud как транзакционный сервер.
Внутри проектной рабочей копии не публикуй .systems в Git; добавление в ignore согласуй с соглашениями проекта.
Не перезаписывай init поверх существующего состояния. Для следующего запуска используй отдельную
рабочую копию либо архивируй завершённое состояние после проверки и явного поручения.
Нет автоматического очистителя резервирований: при crash сохрани blocked result активной попытки,
затем повтори; не снимай резервирование у ещё работающего исполнителя.

До 5 попыток одного task ID, до 30 dispatch по умолчанию (максимум 100 на run), deadline 1800 секунд
по умолчанию (максимум сутки). Если закончился лимит — сохрани отчёт и stop; не обходи его сменой ID/run.
Это лимиты координации на границах команд; они не прерывают модель/процесс по таймеру.
Главный чат обязан использовать bounded wait/interrupt и передавать remaining limits исполнителям.
Денежный или токенный лимит нельзя гарантировать без достоверной телеметрии; здесь нет API-вызовов
и финансового контроллера. Модель/reasoning наследуются, каталог навыков не загружается целиком.

Security fail/blocked или safety_block выставляет hold. Основной чат прекращает рискованную работу
и при необходимости прерывает исполнителей. При hold новые задачи — лишь repair/security/design/
research/monitor. Независимый security pass после исправления может снять hold. Для повторной
проверки той же версии повтори failed task ID; старые finding IDs и ограничения сохраняй в отчёте.
Критик не имеет технического права блокировать Git merge; этот gate применяет диспетчер/настроенный CI.
Разногласие developer/critic передай systems-architect, не скрывая security finding.
Более низкий приоритет задачи не разрешает игнорировать риск повышения привилегий или DMA.

## Ворота
- build: точный SDK/CPU/ABI, exit code, предупреждения относительно baseline, хеши артефактов;
- static: подходящие анализаторы и flags, подтверждённые findings, отсутствие нерешённых обязательных дефектов;
- security: границы модели угроз/проверки, memory/DMA/access/lock invariants, нерешённые риски;
- runtime: конкретная VM/HIL, хеш бинарника, load/unload, stress/fuzz limits, reproducer и logs.
Отсутствующая среда/анализатор — blocked для обязательной проверки, не pass.
Нулевые предупреждения, чистый SAST и отсутствие падения не являются доказательством отсутствия всех ошибок.
