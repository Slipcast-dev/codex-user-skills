# Боты и фоновые задачи

## Состояние и доставка

Храни состояние многошагового диалога и прогресс долговременных задач в устойчивом хранилище, когда потеря процесса недопустима. Память процесса подходит только для явно временных данных. Не обещай exactly-once: при at-least-once доставке используй стабильный идентификатор события и атомарную фиксацию обработки вместе с локальным результатом.

Для внешнего эффекта используй поддерживаемый провайдером ключ идемпотентности или сверку результата после неизвестного исхода. Если API этого не позволяет, зафиксируй неопределённый исход и не повторяй опасную запись вслепую. Для связи транзакции и очереди рассматривай outbox; получатель всё равно должен обрабатывать дубликаты.

До подтверждения входящего события или продвижения polling offset зафиксируй событие/задание устойчиво. Проверь, когда конкретная библиотека подтверждает обновление: сохранённая FSM не закрывает промежуток между получением события и созданием задания. Если библиотека подтверждает слишком рано, выбери поддерживаемый механизм управления приёмом или честно укажи ограничение гарантии.

Задание в running должно иметь lease/heartbeat либо другой явный механизм обнаружения прерванного исполнителя. При восстановлении различай безопасный повтор локальной работы и неизвестный внешний эффект, который сначала требует сверки.

## Выполнение

Ограничивай размер очереди и параллелизм, задавай таймаут операции и общий deadline. Retry только для временных ошибок, с backoff, jitter, Retry-After и пределом попыток. Ошибки данных и авторизации не лечатся повтором. Исчерпанные задания переводи в карантин с причиной и безопасным способом повторного запуска.

При остановке перестань брать новые задания, дождись текущих в пределах grace period, сохрани checkpoint и освободи ресурсы. Отмена не должна превращаться в бесконечный retry. Для единственного polling-потребителя исключи одновременный запуск конфликтующих экземпляров; модель масштабирования проверь по текущей документации библиотеки.

## Проверка

На локальных фикстурах проверь повтор одного события, сбой между эффектом и подтверждением, перезапуск, заполнение очереди и отмену. Проверяй количество внешних эффектов, сохранённый прогресс и возможность восстановления. Не отправляй реальные сообщения людям ради теста без соответствующего разрешения.
