# Telegram и асинхронные сервисы

- Структура: `config`, `bot`, `routers`, `services`, `repositories`, `middlewares`, `tests`.
- Загружай конфигурацию один раз при старте и заверши процесс с понятной ошибкой при отсутствии обязательного секрета.
- Используй async-клиенты и не блокируй event loop синхронным I/O; CPU-тяжелую работу выноси в executor или отдельный worker.
- Разделяй обработчики сообщений и бизнес-логику, чтобы ее можно было тестировать без Telegram API.
- На внешних API применяй timeout, ограничение параллелизма, retry только для временных ошибок и идемпотентные операции.
- Не помещай токены в callback data, URL, сообщения об ошибках или telemetry.
