# Compact operational contract

Keep name and description in supported frontmatter. Do not invent runtime metadata keys for this template.

- Scope: what outcome activates this skill, exclusions and the closest alternate route.
- Inputs: required evidence, discoverable facts and safe assumptions; ask only for consequential unknowns.
- Scale: quick, standard or higher-risk work; choose by failure consequences, not arbitrary task length.
- Capabilities: required tool roles, discovery and fallback; never invent an unavailable API.
- Effects: distinguish read, local edit and external mutation; reuse valid existing authorization and preserve environment restrictions. Silence is not approval.
- Workflow: the smallest coherent sequence; avoid duplicating a shared implementation process.
- Completion: observable result, acceptance checks, pass/partial/fail/unverified states.
- Recovery: deadlines, bounded retry, cancellation, checkpoints and rollback when relevant.
- Freshness: cite official sources and last verification for changing product claims; durable methodology needs no arbitrary expiry date.
- Evaluation: realistic positive, negative, missing-tool and failure cases, with expected observable behavior.

Do not mechanically append all fields to every tiny skill. Store detailed mode-specific methods in references, with conditions explaining when to read them.
