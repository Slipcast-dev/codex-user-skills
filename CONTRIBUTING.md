# Участие в проекте

Спасибо за помощь в сопровождении каталога пользовательских навыков Codex. Изменения принимаются через pull request.

## Перед изменением

1. Найдите существующий навык в [каталоге](CATALOG.md) и проверьте открытые [issues](https://github.com/Slipcast-dev/codex-user-skills/issues).
2. Убедитесь, что имеете право распространять добавляемые файлы. Приложите лицензию, сведения об авторе и ссылку на исходный проект, если материал заимствован.
3. Прочитайте [правила общения](CODE_OF_CONDUCT.md). Об уязвимостях сообщайте по [политике безопасности](SECURITY.md).

## Новый навык

- Добавьте полную папку в `skills/<уникальное-имя>/`.
- Обязателен `SKILL.md` с YAML frontmatter, содержащим `name` и `description`.
- Имя папки должно совпадать с `name`; описание должно ясно объяснять назначение навыка.
- Используйте относительные пути для ресурсов внутри навыка. Проверьте ссылки на соседние навыки и укажите внешние зависимости.
- Не добавляйте API-ключи, пароли, персональные данные, локальные пути пользователя, журналы и кэш.
- Сохраните исходные `LICENSE`, `NOTICE` и сведения об авторах. Не заменяйте чужую лицензию лицензией этого репозитория.

Системные навыки Codex и содержимое установленных плагинов выходят за рамки этой коллекции.

## Каталог и категории

Для каждого навыка нужны корректные сведения в [catalog/skills.json](catalog/skills.json): имя, описание, основная категория, путь, происхождение и лицензия. Выбирайте категорию по назначению; происхождение хранится отдельно.

Страницы категорий и [CATALOG.md](CATALOG.md) должны соответствовать каталогу. После изменения `catalog/skills.json` выполните:

```sh
python3 scripts/build_catalog.py
python3 scripts/check_catalog.py
```

Генератор обновляет страницы категорий, счётчики и сведения о лицензиях. Не меняйте автоматически категории остальных навыков из-за правки одного описания.

## Pull request

В описании укажите:

- задачу и результат изменения;
- затронутые навыки и категорию;
- источник и лицензию новых материалов;
- выполненные проверки и известные ограничения.

Проверьте доступность локальных ссылок, соответствие каталога файлам и отсутствие секретов. Дождитесь проверки GitHub Actions. Проверка структуры каталога не заменяет проверку качества или безопасности самого навыка; не запускайте чужие сценарии только ради прохождения проверки.

Для инструментов сопровождения могут потребоваться Python 3.11 или новее. Собственные зависимости навыков определяются их документацией.
